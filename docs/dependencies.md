# Dependencies, licenses, and integrity policy

U1 uses four direct packages, all pinned exactly in `package.json` and `package-lock.json`:

| Package | Purpose | License | Platform / removal boundary |
|---|---|---|---|
| React 19.2.7 | minimal UI shell boundary | MIT | portable bundled JavaScript; removable with the UI render layer |
| React DOM 19.2.7 | browser renderer | MIT | portable bundled JavaScript; removed together with React |
| TypeScript 6.0.3 | type checking/test compilation | Apache-2.0 | build-only, no target install; removable only by replacing the typed build |
| Vite 8.2.0 | deterministic static build | MIT | build-only; cached Darwin ARM64 Rolldown binding verified; replaceable at the build boundary |

Transitive package license declarations are checked from the installed locked tree by
`scripts/check-licenses.mjs`; package-time inventory is generated by `scripts/package-plugin.mjs`.
The plugin package contains `LICENSES/dependencies.json`, available
installed license texts, a machine-readable list of packages whose tarball omitted a license text,
an explicit project-license status, and its own `checksums.json`. A missing text blocks a public
release notice review but does not erase the package's declared SPDX license. Build-time dependencies
never install on the target machine.

The repository source has no owner-selected redistribution license yet and is therefore treated as
**UNLICENSED / not for redistribution**. A public package release is blocked until the owner adds a
project license and completes notice review. This is intentional rather than silently assigning a
license on the owner's behalf.

Network installation is not part of U1 verification. The initial workspace was bootstrapped only from
packages already present in the local npm content cache. Future maintainers may use `npm ci` in an
approved dependency-fetching environment; offline verification after installation uses `npm run verify`.

The available cache contained Lightning CSS 1.33.0 but not its matching Darwin ARM64 optional binary
(only the 1.32.0 binary was present). U1 therefore sets Vite `build.cssMinify: false`; CSS is still
processed and bundled, but not compressed. This avoids mixing native package versions or fetching a
binary. It can be revisited only through a separately reviewed dependency-lock update.

No online maintenance or vulnerability-freshness claim was made in U1 because network access was
forbidden. The evidence covers exact cached versions, declared licenses, target architecture presence,
offline build behavior, and removal boundaries. Freshness/security review remains a release gate.
